# familink-core

Familink の世界観と絶対ルールを定義する最上位 Skill。他の全 Skill はこの定義に従う。

## 役割
- Familink の全方針の単一のソース
- 他 Skill が判断に迷ったときの基準
- ブランド・トーン・品質基準の番人

- 本 SKILL.md
- `CLAUDE.md`
- `docs/worklog.md`（過去判断の履歴）
- `docs/development-workflow.md`
- `docs/mobile-operation.md`

## Familink の定義
- サービス名: Familink
- キャッチ: 家族の予定も、やることも、ひとつに。
- コンセプト: 家族みんなで子育てをチームに。
- ターゲット: 30〜40 代の子持ち共働き世帯（夫婦 / 家族 / カップル）
- 提供価値: 予定 / タスク / 持ち物 / 体調 / お金 / 家族共有ボード / 書類 / Hoku AI を一元管理し、共有漏れ・準備漏れ・負担の偏りを減らす

## Hoku（AIアシスタント）絶対ルール
- 名前: Hoku
- 立ち位置: 家族に寄り添うAI
- 口調: 少しラフなタメ語
- 既存デザイン変更禁止
- 長文NG（基本 2〜4 行で完結）
- 禁止語: 「承知しました」「かしこまりました」「超おすすめ」
- 実データ以外を推測・断定しない
- 確認なしに勝手に操作しない

## 価格方針
- 無料プラン + 月額 480 円プレミアム
- 30 日全開放トライアルを検討
- プレミアム候補: ボード追加 / プレミアムアバター / Hoku 強化 / テンプレート拡張

## デザイン方針
- シンプル / 上質 / 家族向け / 温かい
- 安っぽい絵文字乱用禁止
- 子どもっぽすぎない
- App Store に出して恥ずかしくない品質
- スマホ最優先 / PC でも崩れない

## 現行構成（重要）
- シングル HTML / Vanilla JS / CSS
- LocalStorage 永続化
- 勝手に React Native / Supabase へ移行しない
- 認証 / DB / 課金 / LocalStorage 構造 / 大規模リファクタリングは必ず事前確認

## Familink での判断基準
1. 家族共働き世帯のリアルな課題を解いているか
2. Hoku の人格を壊していないか
3. App Store に出せる品質か
4. 現行構成（HTML / Vanilla JS / LocalStorage）を破壊していないか
5. 子どもっぽさ / 安っぽさが出ていないか

## やること
- 全 Skill の判断のベースを提供する
- ブランド / Hoku 口調 / 禁止語に反する変更を検出して止める
- 価格・UI 方針との整合性をチェック

## やらないこと
- 個別の実装はしない（実装系 Skill に委ねる）
- 戦略判断や事業判断は ceo-strategy / product-owner に委ねる
- アプリ本体コードを直接編集しない

## 作業前チェック
- どの方針に該当するタスクか宣言する
- ブランド / Hoku / 価格 / 構成 のどこに影響するかを 1 行で書く

## 作業後チェック
- 変更が Hoku 口調 / 禁止語 / デザイン方針に反していないか目視
- App Store 公開前提として恥ずかしくない仕上がりか自問

## テスト観点
- Hoku 文言が 4 行以内で完結しているか
- 禁止語が混入していないか
- 子どもっぽい絵文字が増えていないか

## バグ対応観点
- 「Familink らしさ」を壊すバグ（口調崩壊・UI 崩れ）は優先度 S として扱う

## iPhone 確認観点
- Safari (iPhone) で Hoku のセリフが折り返しで崩れていないか
- フォント / 余白 / タップ領域が小さすぎないか

## 出力形式
判断時は以下を必ず添える。
```
【familink-core 判定】
・対象: <変更対象>
・該当方針: <ブランド/Hoku/価格/UI/構成>
・判定: OK / NG / 要確認
・根拠: <1〜2行>
```

## レビューすべきポイント
- ブランドからのズレがないか
- Hoku の口調・禁止語が守られているか

## Claude Code への指示形式
- 「familink-core 観点でこの変更を評価して」
- 「Hoku 文言として familink-core に反していないか確認して」
