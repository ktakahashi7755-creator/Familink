01 — Executive Summary

エグゼクティブサマリー

Familink は、子育て家庭の 予定・タスク・家計・体調・準備・買い物 を、家族向け AI「Hoku」とともに一元管理する 家族向けスーパーアプリ です。

共働き・子育て家庭の毎日は、Google カレンダー / LINE / 紙プリント / 家計簿アプリ / 口頭連絡 に情報が分散し、共有漏れが「朝の戦争」と夫婦間摩擦を生んでいます。既存アプリはカレンダー特化・家計特化・メモ特化と縦割りで、「家族運営」という横軸を担うプロダクトが存在しない。

Familink はその横軸を、8 機能の統合 + Hoku AI 入力支援 で埋めます。MVP v1.4 が稼働中・自動テスト 785 件全 PASS の品質を確保。本ラウンドでは App Store 公開・実ユーザー検証・初期マーケティングの資金（¥150 万）を求めます。

02 — Problem

解決する課題

子育て家庭が 1 日に管理する情報の種類は、他の世代より圧倒的に多い。ツールは個人最適に設計されており、家族というチームに向けたプロダクトが存在しない。

領域現状の管理手段問題
予定Google / iPhone カレンダー（個人ごと）家族で見るのに複数アプリ、見落とし多発
タスクLINE / 記憶誰がいつまでにが曖昧、摩擦の原因
持ち物準備紙のプリント / 記憶朝の忘れ物・準備漏れが毎週起きる
体調記録メモ帳 / 記憶発熱日・薬の記録が次回受診で分からない
家計別アプリ（一方しか見ない）夫婦の一方のみ把握、もう一方が見えない
買い物口頭 / 紙メモ共有漏れ・重複購入・伝達のストレス
家庭内オペレーションは、まだ DX されていない。

TimeTree・Google カレンダー・Zaim 等の既存サービスは、それぞれ単一機能に特化。家族全員が複数アプリを使い分ける摩擦と、機能間の連携ゼロが根本問題です。

03 — Solution

ソリューション

家族で使う 8 機能を 1 つのスマホアプリに統合。すべて家族メンバー単位で紐付き、「誰のために・誰がやり・いつ・いくら・何が必要か」が 家族で共有 されます。

04 — Hoku AI

Hoku AI — 差別化の核

Hoku は家族向け文脈に最適化した軽量 AI アシスタント。短い自然な日本語を、適切な機能へ振り分けます。

入力例反映先
「明日18時、星旺スイミング」カレンダー（子どもの予定として登録）
「スーパーで3,200円」家計（支出として記録）
「星汰37.8度 咳」体調管理（体温・症状を家族メンバーに紐付け）
「明日の準備に体操服」準備リスト（翌日持ち物へ追加）
「牛乳追加」買い物リスト（今すぐ欄へ追加）
日本育児文化に特化
体温・教科・行事名・学期・全角漢数字を理解。汎用 AI との根本差異。
完全ローカル実行
外部 API 不要。家族情報が外部に送信されないプライバシー最優先設計。
確認モーダル必須
誤分類しても自動保存しない安全設計。医療・税務ガードレール内蔵。
文脈保持 5 ターン
「やっぱ花子で」「さっきのキャンセル」が通じる会話継続。

05 — Competitive Moat

競合優位 — なぜ真似されないか

ファミリーアプリは多数あるが、Familink が構築しようとしているモートは 4 層。

🔒
家族データの蓄積
カレンダー・家計・体調の 3 ヶ月以上の記録が蓄積されると、スイッチングコストは著しく上昇。データを持つ家族は離れない。
🇯🇵
日本育児文化への特化
Hoku は日本の学校制度・給食・行事・育児文化に特化。グローバル大手が模倣しようとしても、この文脈理解の再現には年単位かかる。
🏠
家族 OS として先着
「家族の日常オペレーション基盤」として先に定着したプロダクトは乗り換えられない。エネルギー管理 / 住宅 / 保険への拡張窓口にもなる。
🌐
ネットワーク効果
1 家族が導入すると祖父母・親戚まで巻き込む。「家族グループ」単位の課金により、個人 SaaS より高いリテンションと口コミ拡散を設計。
家族データ × 日本文化特化 × 先着 OS = 真似されにくい複合モート

12 — Risks & Assumptions

リスクと前提
リスク現状の前提対策
競合大手の模倣 TimeTree 等の既存サービスが家族 OS 化しない データ蓄積 + 日本文化特化の複合モートで差別化。先着効果を最大化。
課金転換率が低い 30 日トライアル後に 5% 以上が有料転換 プレミアム機能の価値を日常で体感させる設計。家族同期がキラー機能。
App Store 審査リジェクト 審査ガイドライン準拠で 1 回通過 App Store 審査チェックリスト整備済み。ガイドライン逸脱項目ゼロ。
プライバシー規制強化 ローカル保存で個人情報外部送信なし クラウド化時は Row Level Security + データ最小化設計を適用。
1 人開発の限界 ファウンダー 1 人で MVP まで完成 AI 駆動開発（Claude Code）で速度担保。資金調達後に外部リソース追加。

13 — Security / Privacy

セキュリティ / プライバシー方針
  • 現 Web 版：ユーザーが選択したファイル / 入力データのみを扱い、外部サーバーへ送信しない
  • 外部カレンダーは許可なく自動取得しない（ICS 手動取込のみ）
  • 将来のクラウド化では Row Level Security（家族グループ単位アクセス制御）を前提設計
  • API Secret をフロントエンドに置かない設計（GitHub Pages 公開前提）
  • Hoku AI のローカル分類エンジンは入力テキストを外部 API に送信しない
  • 体温・病名・家計情報等の機微データは端末内のみに保持（MVP 段階）

App Store 公開時に Apple のプライバシーラベル・App Tracking Transparency 対応を完了予定。
