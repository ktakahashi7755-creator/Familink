# AI 開発タスク分解テンプレート

AI（Claude Code 等）に渡すタスクは、必ず以下の形式で 1 タスク単位に分解する。
**「全部作って」は禁止。** 1 機能 / 1 改善 / 1 画面 / 1 コンポーネント / 1 保存処理 /
1 テスト追加 / 1 ドキュメント更新 = 1 タスク。

---

## タスク記述テンプレート

```
### TASK-XXX: <タスク名>

- 目的:
  （なぜこのタスクが必要か。ユーザー成功体験 / US との紐付けを 1-2 行で）

- 対象ファイル:
  - app-source/familink.html（該当関数 / 該当画面 ID）
  - docs/...（更新するドキュメント）

- 実装内容:
  （何をどう変えるか。具体的な関数名・画面 ID・データキーまで明記。
   AI が判断に迷わない粒度にする）

- 受け入れ条件:
  - [ ] （満たすべき機能要件を箇条書き。テスト可能な形で）
  - [ ] ...

- テスト条件:
  - [ ] （実行する VM テスト / 手動確認項目）
  - [ ] 既存 VM スイート 全 PASS（退行ゼロ）

- 完了条件:
  - [ ] 受け入れ条件すべて満たす
  - [ ] テスト条件すべて緑
  - [ ] 構文 check OK
  - [ ] app-source ⇔ docs/index.html の md5 一致
  - [ ] worklog 追記
  - [ ] コミット（1 タスク = 1 論理コミット）

- 依存タスク:
  （先に完了している必要があるタスク ID。なければ「なし」）

- 優先度:
  S / A / B / C

- 注意事項:
  （既存機能を壊さないための注意。触ってはいけない箇所など）
```

## タスク粒度の基準

| OK な粒度 | NG な粒度 |
|---|---|
| 「家計画面に固定収支タブを追加」 | 「家計機能を作る」 |
| 「Hoku の login_help intent を追加」 | 「Hoku を賢くする」 |
| 「m-event モーダルの保存処理を実装」 | 「予定機能全部」 |
| 「ICS パーサーの RRULE 対応を追加」 | 「外部カレンダー連携」 |

- AI が **1 回のセッションで安全に実装できる** 大きさ
- 大きすぎるタスクは必ず分割
- 曖昧なタスク（「いい感じにする」等）は禁止
- 完了判定が一意にできる形にする

## AI へ渡す際の指示文（タスク実行プロンプト）

```
あなたはこのプロジェクトの開発担当です。
以下の要件定義・設計書・タスク内容に従って、対象タスクのみ実装してください。

- 勝手な仕様追加は禁止です。
- 既存機能を壊さないでください。
- 1 タスクずつ実装してください。
- 実装後は必ずテストを行ってください。
- 動作確認前に完了扱いにしないでください。

完了後は以下を報告してください：
- テスト結果
- 変更ファイル一覧
- 未対応課題

【参照】
- 要件定義: docs/ai-dev-flow/spec/requirements.md
- 設計書: docs/ai-dev-flow/design/
- タスク内容: <ここに上記テンプレートで記述したタスク>
```

## WBS（development-tasks.md）の書き方

タスクは依存順に並べ、フェーズ・優先度でグルーピング：

```
## マイルストーン M1: <名称>

| ID | タスク名 | 優先度 | 依存 | 状態 |
|---|---|---|---|---|
| TASK-001 | ... | S | なし | 未着手 |
| TASK-002 | ... | A | TASK-001 | 未着手 |
```

状態は 未着手 / 実装中 / レビュー中 / 完了 で更新。
