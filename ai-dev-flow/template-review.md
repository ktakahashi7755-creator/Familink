# レビューテンプレート

モック・要件・設計・実装を、6 視点で違和感を全潰しするためのテンプレート。
Phase 8（設計レビュー）と Phase 12（実装後レビュー）で使う。

---

## 6 視点レビュー

各視点で「良い点」「違和感 / 指摘」「重要度」を記録する。

### 1. ユーザー目線
- 本当に使いやすいか / 何をすればいいか分かるか
- 毎日使う理由があるか / 不要な機能が多すぎないか
- 子育て家庭が 3 秒で画面の目的を理解できるか

### 2. PdM 目線
- プロダクト価値が明確か / MVP 範囲が適切か
- 事業化の道筋があるか / 優先順位が正しいか
- ユーザー成功体験と機能がつながっているか

### 3. エンジニア目線
- 実装可能か / 設計が破綻していないか
- データ構造が妥当か / 責務が分かれているか
- 保守しやすいか / 拡張しやすいか

### 4. QA 目線
- テスト可能な要件か / 異常系があるか
- 回帰テストが考慮されているか
- 保存 / 編集 / 削除が検証できるか

### 5. デザイナー目線
- UI に違和感がないか / 視線誘導が自然か
- 余白が適切か / スマホで見やすいか
- 横スクロールが出ていないか / 空状態・エラー状態が自然か

### 6. 投資家 / 事業目線
- 伸びる可能性があるか / マネタイズできそうか
- 競合との差別化があるか / 説明しやすいか

## 違和感リスト（issues-to-fix.md）

```
| ID | 指摘 | 視点 | 重要度 | 修正方針 | 状態 |
|---|---|---|---|---|---|
| ISS-001 | ... | ユーザー | High | ... | 未対応 |
| ISS-002 | ... | QA | Mid | ... | 対応中 |
```

- 重要度：High（次フェーズへ進む前に必須）/ Mid / Low
- 状態：未対応 / 対応中 / 対応済 / 見送り（理由明記）

---

## 最終レビュー（final-review.md）

```
## 最終レビュー: <フェーズ>
## 判定: GO / NO-GO

### High 指摘の解消状況
- ISS-001 → 対応済（コミット xxxxxxx）
- ...

### 残課題（Mid / Low）
- ...（次フェーズ or バックログへ）

### 結論
「これでいけそう」判定の根拠を 2-3 行で。
```

判定が GO になるまで「修正 → 再レビュー」を繰り返す。
**High 指摘が 1 件でも残っていれば NO-GO。**

## ChatGPT ブラッシュアップ観点（Phase 7 / chatgpt-feedback.md）

外部 AI に md 群を渡す際のチェック観点：

- 表現が分かりやすいか
- 抜け漏れがないか / 矛盾がないか
- 曖昧な表現がないか / AI が誤解しそうな表現がないか
- 実装可能な粒度か
- ユーザー成功体験と機能がつながっているか
- BR 計算式が明確か
- 設計と要件が一致しているか
- テスト可能な要件になっているか

指摘は issues-to-fix.md に統合して潰す。
