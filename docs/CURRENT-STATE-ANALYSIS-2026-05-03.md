# Familink 現状分析レポート（Wave 24 / 2026-05-03）

**対象コミット：** `467e4bc`（MVP v0.1 + バックアップマニフェスト後）
**対象ファイル：** `app-source/familink.html`（8,463 行 / 単一 HTML）
**目的：** 再開発・引き継ぎのため、現時点の Familink を客観的に棚卸し

---

## 1. 現在のプロダクト概要

Familink は **「家族みんなで毎日をチームに」** をコンセプトとする、子育て家庭向けの家族運営アプリ。
17 画面で 9 コア機能を統合し、家族運営 AI「Hoku」が伴走する設計。

**現状形態：**
- 単一 HTML ファイル（インライン CSS / Vanilla JS）
- React / Next / 依存ライブラリ ゼロ
- 外部 API ゼロ（クラウド / AI / 認証 すべてなし）
- LocalStorage（key: `familink_v3`）に全データ保存
- GitHub Pages でデプロイ（HTTPS）

**規模：**
- 行数：8,463
- 画面：17（書類保管庫 5 画面は Wave 15 で意図撤廃）
- 関数：約 230
- 主要 LS フィールド：26（PERSIST 配列）
- 自動テスト：301/301 PASS（Playwright Chromium）

## 2. 現在実装されている機能（コア 10 領域）

## 8. 設計上の問題

### 8.1 構造的な制約
- **単一 HTML 8,463 行** — エディタでの可読性が低下、関数索引が必要
- **依存ライブラリゼロ** — 軽量だが、複雑機能（Web Push / カメラ / クラウド同期）の実装に制限
- **LocalStorage 単独** — 端末間同期が物理的に不可能

### 8.2 拡張性の制約
- 家族同期：QR コード方式で最小実装可能だが LS 構造変更を伴う
- AI 応答：現在は正規表現分類器、文脈応答には会話履歴ストア追加要
- 課金：StoreKit / Play Billing は WKWebView ラッパー化が必要

### 8.3 責務の重複
- BOARD_TYPE_META（旧）と INTENT_META（新）が並立
- 体調管理（s-health）と health intent ボードが並立

## 9. UX 上の問題

### 良好（A 評価）
- ホーム動作 / タスク完了 → 削除フロー / 家計メンバータブ / ボード作成 7 用途
- 4 viewport 整合（iPhone SE / 13 / 15 Plus / Pro Max）
- アクセシビリティ（aria-label 19 件）
- オンボーディング 4 ステップ

### 改善余地（B 評価）
- Hoku 音声：iOS Safari で動かないケースあり（フォールバックは整備済）
- カメラアイコン：「家族にシェア」だが投稿モーダル開くのみ（実カメラ起動なし）
- プレミアム機能の半数が「予定」表記 → 課金転換に弱い
- 通知：センター UI のみで自動プッシュなし

### 弱い（C 評価 / ユニコーン障壁）
- 家族 2 端末同期がない → コア提案「家族で共有」が物理未成立
- 継続利用フックがない（ストリーク / 週次サマリー / 朝の通知）
- Hoku 文脈応答なし → AI 体験中堅

## サインオフ

Familink MVP v0.1 は **コード上 100% 動作する状態**（301 自動テスト PASS）に到達しているが、
**ユニコーンとして成立する** には以下 3 軸の追加実装が必要：

1. 家族 2 端末同期（コア提案の物理実現）
2. 継続利用フック（リテンション）
3. プレミアム実体価値（収益化）

詳細な再開発ロードマップは `REDEV-ROADMAP-2026-05-03.md` 参照。
