## 実機確認で見るべきポイント

1. **家族ボード**：上部の準備カードが消え、共有投稿のみのシンプルさ
2. **ホーム → ＋ ボードを追加**：
   - 7 用途のカードが 2×4 グリッドで一目瞭然
   - 押すたびに直下の説明文がスムーズに切り替わる
   - 体調管理 を押すと医療注記が表示される
3. **新規ボード作成後**：
   - 詳細画面に遷移すると「白紙ではない」状態
   - 用途ヒーロー（アイコン + 説明）
   - 入力例チップ（最大 5 個 / 薄い破線で）
   - prep/shopping/submissions は自動セクション 2 つ
   - 下部固定の青い「＋ {追加文言}」ボタン
4. **追加ボタンタップ**：モーダルが必ず開く（押せないボタンなし）
5. **項目追加モーダル**：
   - タイトルが intent 別の placeholder（例：牛乳 / 例：37.5度の発熱）
   - prep 系では自動でセクション「今すぐ / 今日 / 今週」が初期選択
6. **保存後**：項目が即一覧に反映、リロード後も保持
7. 既存ボード（旧データ / `intent` 未定義）も問題なく開く（後方互換）

## サインオフ

> Wave 17：「ボード機能の白紙感」という根本 UX 問題を解消した。
>
> - 家族ボードと準備リストの責務を完全分離
> - 用途タイプを 3 → 7 intent に拡張（ユーザー語彙ベース）
> - 用途別の自動初期化（セクション / 説明 / 追加ボタン文言 / 入力例 / プレースホルダー）
> - 追加ボタンを固定配置でタブバーと干渉しない設計に
> - 既存データ完全互換（getIntentMeta で旧データも適切にマッピング）
>
> 行数：8538 → 8665（+127 / 機能拡張に対し最小増分）
> 既存 17 画面：すべて維持
> LocalStorage 構造：追加フィールド 1 つのみ（`customBoards[i].intent`）
> Playwright 動作確認：全 PASS / pageerror 0 件
>
> Wave 18 候補：iOS 実機検証 + Hoku 音声安定化 + 曜日ルーティン準備。
