# Familink プロダクトロードマップ

このドキュメントは、Familink の機能優先度と段階的リリース計画の **正本** です。
個別仕様は `docs/mvp-requirements.md`、価格は `docs/premium-strategy.md`、UI 基準は `docs/ui-ux-guideline.md` を参照してください。

---

## 1. プロダクトビジョン

**「家族みんなで子育てをチームにするアプリ」**

3 児パパ・ママ・祖父母を含めた家族全員が、子育てをチームで回せる状態を作る。単なる予定共有アプリではなく、家族の生活導線に入り込むハブを目指す。

---

## 2. 北極星指標（North Star Metric）

候補（MVP リリース後に確定）：

- **週次アクティブ家族数（WAF: Weekly Active Families）** — 1 家族 = 1 ユニット
- 補助指標：1 家族あたりの週次操作数 / 招待成立率 / 30 日継続率 / 有料転換率

---

## 3. 段階別ロードマップ

### Phase 0: 素地整備（〜MVP 着手前）

- リポジトリ整備（`.gitignore`, `CLAUDE.md`, `docs/`, Skills 配置）✅
- アプリ本体 HTML の取り込み（PC からの push 待ち）

### Phase 1: MVP（短期 / 公開直前まで）

公開に必須の最小セット。詳細は `docs/mvp-requirements.md`。

- ログイン / ホーム
- 予定共有
- タスク管理
- 家族ボード
- Hoku の基本導線
- プレミアム制限の基礎
- データ保存（LocalStorage）
- 最低限の手動テスト通過
- App Store 公開に必要な品質

### Phase 2: 公開直後（中期 / 〜獲得初期）

- 家計管理
- 体調記録
- 習い事記録
- 持ち物・準備リスト
- 通知
- 招待機能
- 画像・アイコン選択
- Hoku アニメーション強化
- 初期マネタイズ：月額 480 円プレミアム

### Phase 3: 拡張（中長期 / 〜事業化）

- Supabase 等のサーバー連携（LocalStorage → クラウド同期）
- React Native への移行検討
- 上位プラン（680 / 780 / 980 円）の段階導入
- 家族レポート / AI による予定・タスク整理
- TestFlight / オーガニック獲得 / 口コミ施策

### Phase 4: スーパーアプリ化（長期）

- Hoku を家族 AI アシスタントとして成長
- 子育て家庭向けの統合プラットフォーム化
- 事業売却 / 資金調達 / ユニコーン化を狙える状態

---

## 4. 後回し / 実装しない（明示）

短期〜中期では **やらない** ことを明示してスコープを守る：

- 過度なアバター機能（小規模の選択肢追加は OK）
- 複雑すぎるゲーミフィケーション
- SNS 機能（家族外への発信）
- 高度すぎる AI 機能（自律生成・複雑な分析）
- MVP に不要な大量機能の同時投入

判断は `familink-product-owner` Skill に委ねる。

---

## 5. 優先度判定基準

§7 の S/A/B/C ルール（`CLAUDE.md`）と、§10.3 のユニコーン視点チェックリストを併用する。

- **S**：致命バグ。即時着手
- **A**：公開前に直したい重要改善
- **B**：公開後でよい改善
- **C**：将来機能

ユニコーン視点で YES が過半に満たない機能は B / C に格下げ。

---

## 6. 更新ルール

- 機能を新規発案したら、まずこのドキュメントに Phase / 優先度を記録
- リリース判断時は `familink-product-owner` で再評価
- ロードマップ変更は worklog にも要約を記録
