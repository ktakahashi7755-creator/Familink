# 07. Hoku AI エージェント設計

## 7.1 位置づけ
Hoku はキャラクターではなく **「家族を支えるガイド役 / 話すだけで動くエージェント」**。
右下に常駐（フローティング）し、吹き出しで案内、軽い呼吸/浮遊アニメ（過度にしない・reduced-motion対応）。

## 7.2 人格・口調
- やさしい・信頼感・家族向け。短文応答。押し付けない。装飾絵文字は使わない。
- 例：「今日は3件あります。忘れ物がないか確認しておくと安心です。」
- 最終判断は家族・専門家へ、を画面常設（医療/家計/AIの免責）。

## 7.3 会話データ
- 実行時メッセージ配列 `_hokuMsgs = [{role:'user'|'assistant'|'loading', content}]`（`renderHokuMsgs()` で描画）。
- 文脈 `S.hokuContext`（直近ターンの意図等・個人キー＝家族に共有しない）。

## 7.4 応答パイプライン `sendHokuMsg(text)`
```
入力(空は送らない) → user/loading を積む → renderHokuMsgs
  ├─ (プレミアム＋会話AIモード＋上限内) → 外部AIへ _hokuTryChat(text)（成功で採用）
  └─ それ以外/失敗 → ローカル Hoku
        parseHokuIntent(text) → 意図＋信頼度
        ├─ 追加系(_add)＆信頼度高 → executeHokuAction（予定/タスク/買い物/準備/家計メモ）＋確認
        ├─ 参照系(_view) → executeHokuAction（今日の予定/今週のタスク/家計 等の要約）
        └─ 弱い一致 → hokuLocalAnswer（案内文）
  → loading除去 → assistant応答を積む → 文脈更新 → 再描画 → キュー処理
```
- 取りこぼし防止：処理中の入力は `_hokuQueue` に積み、順番に処理。

## 7.5 エージェント実行（executeHokuAction）
- 追加系意図（例「来週月曜15時に太郎の歯医者を入れて」）→ 予定を作成し、リマインド/準備リストまで案内。
- 参照系（例「今日の予定おしえて」）→ 実データ（S.events等）を参照して要約。
- 破壊的/曖昧な操作は確認フローを挟む（勝手に消さない）。

## 7.6 意図解析（parseHokuIntent）
- 日本語の口語から「カテゴリ（予定/タスク/買い物/準備/家計/体調/ボード/通知…）」「操作（追加/参照/通知）」「エンティティ（日時/対象/金額/品目）」を抽出。
- カテゴリ語彙 `VOICE_TRIGGER_CAT_NOUN` 等でトリガ判定。誤爆を避けるため明示依頼（「通知して」等）を優先。
- 信頼度でしきい値制御（高→実行、中→確認、低→案内）。

## 7.7 音声入力
- 端末の Web Speech API（`SpeechRecognition`）。音声データはサーバへ送らない（プライバシー）。非対応端末はキーボード入力へフォールバック。

## 7.8 会話AIモード（任意・プレミアム）
- Edge Function `hoku`（Deno）経由で外部AI（OpenAI等）に自然文応答を依頼。**キーはサーバのみ**。
- フェアユース上限（`_hokuAiUnderCap`）内でAI、超過時は優しくローカル Hoku へ切替（赤字防止）。
- 1日の相談回数：無料5回・プレミアム無制限（`PREMIUM_FEATURES.hokuDaily`）＋当日購入ボーナス。

## 7.9 UI
- `s-hoku`：会話ログ・サジェスト質問（見る系/入れる系）・残回数・音声ボタン・入力欄・送信。
- 常駐フローティング（`#hoku-fab`）：ドラッグ移動・タップで s-hoku。着せ替え（§ファミコイン）でスキン反映。
- 空状態は温かい呼びかけ（「〇〇さん、何でも聞いて！」）。

## 7.10 Edge Function `hoku`（サーバ・要デプロイ）
- 入力：ユーザーのテキスト＋文脈。出力：短い応答（＋必要なら実行提案）。
- セキュリティ：APIキーはシークレット。会話モード利用時のみテキストを外部送信し、学習非利用（プライバシーポリシーに明記）。

## 7.11 品質基準
- 空入力を送らない・XSSエスケープ・短文・やさしい語調・実データ参照の正確性。
- 詳細指針：`docs/hoku-guideline.md` / `docs/hoku-intent-engine.md`。
