## 2. 正本の原則（1 情報 1 箇所）

| 情報 | 正本 |
|---|---|
| 開発運用ルール（開発憲法） | `CLAUDE.md` |
| 現行仕様（本体系） | `docs/spec-v3/`（本書 00〜12） |
| 機能優先度・フェーズ計画 | `docs/product-roadmap.md`（01 が参照） |
| 作業履歴 | `docs/worklog.md`（追記のみ） |
| サーバ有効化手順 | `docs/BILLING-SETUP.md` / `docs/WEB-PUSH-SETUP.md`（06/12 が参照） |
| Supabase スキーマ SQL | `docs/supabase-apply-all.sql` ほか（05 が参照） |
| 法的文書 | `docs/privacy-policy.*` / `docs/terms-of-use.*` |

本体系と旧ドキュメント（SPEC-v2・architecture-overview 等）が矛盾する場合は**本体系を優先**する。
本体系と実コードが矛盾する場合は、実コードを調査のうえ本体系を改訂する（推測で仕様を書かない）。

## 3. 本体系の運用ルール

1. **実装変更とセットで更新する**: 機能・データ・画面・課金・セキュリティに影響する変更は、対応する文書（02/04/05/07/10 など）を同じコミット群で更新する
2. **版管理**: 各文書ヘッダの「版」を上げ、変更概要を worklog に記録する
3. **要件 ID は再利用しない**: 廃止した FR/NFR は「廃止」と明記して残す（欠番管理）
4. **推測禁止**: 未確認の挙動は「未確認」と明記する。実測（コード行参照・テスト結果）に基づいて書く
5. **世界観の遵守**: 文書自体も Familink の世界観に従う（装飾絵文字を使わない・簡潔でやさしい日本語）
