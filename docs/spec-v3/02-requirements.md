# Familink 要件定義書

**文書番号**: SPEC-v3-02 ／ **版**: 1.0 ／ **作成日**: 2026-07-07 ／ **正本**
**対象読者**: プロダクトオーナー・要件アーキテクト・エンジニア・QA

> 本書は Familink の機能要件・非機能要件の正本である。ビジョンと事業前提は
> `01-product-vision.md`、画面詳細は `04-screens.md`、データ仕様は `05-data-design.md` を参照。
> 各要件には ID（FR/NFR）・優先度（S/A/B/C ※CLAUDE.md §7 の定義）・実装状態を付す。

**実装状態の凡例**: ✅ 実装済み ／ 🔶 実装済み（サーバ設定待ちで無効化中） ／ 🔷 部分実装 ／ ⬜ 未実装（計画）

## 1. システム化の目的と範囲

### 1.1 目的

子育て家庭の予定・タスク・持ち物・体調・家計・書類・写真・連絡を **1 つのアプリ・1 つの世界観**に集約し、
家族全員（親・子・祖父母）が同じ情報を見て動ける状態（＝子育てのチーム化）を実現する。

### 1.2 スコープ

- **対象**: 家族 1 ユニット内の情報共有・記録・リマインド・AI ガイド（Hoku）・課金（プレミアム）
- **対象外**（明示的にやらない）: 家族外への SNS 発信、広告、外部への情報公開、医療診断・金融助言

### 1.3 利用者クラス

| クラス | 説明 | 権限 |
|---|---|---|
| 家族メンバー（親） | 主要利用者。全機能を操作 | 家族データの読み書き |
| 家族メンバー（子・祖父母） | 閲覧＋簡易操作中心 | 家族データの読み書き（UI は同一） |
| 未ログイン利用者 | クラウドなしのローカルモード | 端末内データのみ（全機能利用可） |
| システム（Hoku） | AI ガイド。ユーザー確認を経てのみデータ操作 | 確認モーダル経由の代行のみ |

## 3. 非機能要件（NFR)

### NFR-1 ユーザビリティ

| ID | 要件 | 基準 |
|---|---|---|
| NFR-101 | 3 秒理解 | 忙しい親が各画面の目的を 3 秒で理解できる情報設計 |
| NFR-102 | 片手操作 | スマホ片手操作前提。タップ領域 44×44px 以上 |
| NFR-103 | 迷わない導線 | 押せないボタン・保存されないフォーム・遷移先のない導線・戻るループを残さない |

| NFR-105 | 世界観統一 | 装飾絵文字禁止・ラインアイコン統一・落ち着いた配色（`08-design-system.md`） |

### NFR-2 性能

| ID | 要件 | 基準 |

## 4. 制約条件

1. **技術制約**: 単一 HTML／Vanilla JS／npm 依存ゼロ／許可 CDN は Supabase SDK・Google Fonts のみ（CLAUDE.md §12.1）
2. **データ制約**: LocalStorage 上限 5MB 保守設計。写真 base64 は自動縮小必須
3. **体制制約**: 個人開発（PC＋iPhone の 2 環境）。開始/終了プロトコル・worklog 運用が品質担保の前提
4. **課金制約**: Web/PWA は Stripe、ネイティブストア配布時は IAP。実課金の有効化は人間確認必須
